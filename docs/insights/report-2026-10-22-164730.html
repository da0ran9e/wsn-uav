Custom Skills
Reusable /commands defined in markdown that run a multi-step workflow.
Why for you: You write layer reports repeatedly (L2, L3, likely more). A /report skill could hold the IEEEtran template, the build and page-check steps, and the commit/push/send hand-off, so you only supply the layer and page limit.
mkdir -p .claude/skills/report && cat > .claude/skills/report/SKILL.md <<'EOF' --- name: report description: Write a technical report for a given layer in LaTeX --- 1. Ask for the layer, the format (IEEEtran or long-form) and the page limit if they were not given. 2. Read the relevant source code and any existing reports/ to gather the technical content. 3. Write reports/<layer>/<layer>_report.tex using the IEEEtran template for page-limited papers. 4. Build with `latexmk -pdf -interaction=nonstopmode`. 5. Check the page count with `pdfinfo`. If it exceeds the limit, tighten the text and rebuild. 6. git add the .tex and .pdf, commit, push. 7. Send the PDF to the user. EOF
Hooks
Shell commands that run automatically at lifecycle events such as after a file edit.
Why for you: Most of your 82 Bash calls were probably compile/check loops. A PostToolUse hook can recompile the .tex automatically whenever Claude writes or edits it, so LaTeX errors show up immediately.
{ "hooks": { "PostToolUse": [ { "matcher": "Write|Edit", "hooks": [ { "type": "command", "command": "f=$(jq -r '.tool_input.file_path'); case \"$f\" in *.tex) cd \"$(dirname \"$f\")\" && latexmk -pdf -interaction=nonstopmode -silent \"$(basename \"$f\")\" >/dev/null 2>&1 || echo 'LaTeX build failed' ;; esac" } ] } ] } }

Parallel Agents Draft Report Sections Simultaneously
Instead of writing a 32-page report sequentially, a lead agent can split it into sections (architecture, methodology, results, evaluation) and hand each to a sub-agent that reads the relevant code and data in parallel. The lead then merges the drafts, harmonizes terminology, resolves cross-references and builds the final PDF. Multi-layer reports like your L2 and L3 docs could be produced together in a fraction of the time, with consistent figures and citations across both.
Getting started: Use Claude Code's Task tool to spawn parallel sub-agents, one per section, with TaskCreate/TaskUpdate tracking progress. Keep a shared outline.md and glossary.md that every agent must follow.
Paste into Claude Code:
I need technical reports for Layer 2 and Layer 3 of this project. First, read the repo and write outline.md (sections, owners, target page counts) and glossary.md (canonical terms, symbols, figure naming). Then launch parallel sub-agents, one per major section. Each sub-agent must: (1) read only the code, data and logs relevant to its section, (2) write its section as a separate .tex file under reports/sections/, (3) cite file paths and commit hashes for every claim about implementation, and (4) report back a list of figures and tables it needs. After all agents finish, act as editor: merge the sections, unify terminology using glossary.md, fix cross-references, deduplicate content between the L2 and L3 reports, compile both PDFs, and give me a summary of any inconsistencies you resolved.
